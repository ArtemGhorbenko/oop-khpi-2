# oop-khpi-2
Роботи Горбенко Артема Групи КН-1024В

У ході виконання лабораторної роботи 1 було створено спрощену об'єктну модель системи бронювання номерів готелю. Для перевірки рівності об'єктів класу Room суттєвим полем було обрано roomNumber (унікальний номер кімнати), оскільки він однозначно ідентифікує номер незалежно від його поточного стану (доступний/заброньований). У подальших роботах цю модель можна розвинути, додавши клас Reservation (Бронювання) для відстеження дат заїзду/виїзду, а також впровадити строгі UML-зв'язки типу асоціації або композиції між гостем і номером.


У цій лабораторній роботі я замінив ручне тестування програми на автоматизоване модульне тестування за допомогою фреймворку JUnit 5. Для того щоб тести коректно запускалися, проєкт було переведено на систему збірки Maven із налаштуванням залежностей у файлі pom.xml.
В процесі виконання я зрозумів важливе правило: щоб код було зручно тестувати, його потрібно зробити більш строгим. Тому я вдосконалив метод bookBy у класі Room, додавши туди валідацію вхідних даних. Тепер система не просто ігнорує неправильні дії, а викидає відповідні винятки.
Сам тестовий клас RoomTest я розмістив у правильній директорії src/test/java. Щоб не дублювати код створення об'єктів для кожного з п'яти тестів, я використав анотацію @BeforeEach — вона автоматично готує "чисту" кімнату та гостя перед кожною перевіркою. Логіку програми я перевіряв за допомогою методів assertEquals та assertTrue, а негативні сценарії з помилками — через assertThrows.
