# oop-khpi-2
Роботи Горбенко Артема Групи КН-1024В

У цій лабораторній роботі я створив окремий проєкт для тестування своєї моделі готелю, але цього разу використав фреймворк TestNG замість JUnit Jupiter. Збірка та запуск тестів налаштовані через Maven, а також додано плагін JaCoCo для перевірки покриття коду.
висновки:
Під час виконання я помітив, що TestNG дає набагато більше контролю над тим, як саме запускати тести:
Групування та testng.xml: В JUnit тести зазвичай запускаються всі підряд. У TestNG я розбив тести на групи і створив файл testng.xml. Тепер я можу гнучко керувати запуском, наприклад, сказати програмі: "запусти тільки швидкі smoke-тести" або "прожени весь набір".
Параметризація: Це найзручніша фішка. Замість того, щоб писати купу однакових тестів для перевірки помилок (наприклад, коли ID порожній, null або з пробілами), я створив один метод-провайдер масиву даних invalidGuestData і прив'язав його до одного тесту. Код став набагато чистішим.
Фікстури: Як і в JUnit, тут є підготовка стану, але анотація називається @BeforeMethod. Я використав її для створення чистої кімнати перед кожним тестом, щоб вони не впливали один на одного.
еревірка винятків: У TestNG зручніше перевіряти помилки негативних сценаріїв прямо в анотації @Test(expectedExceptions = ...), що робить сам код тесту коротшим порівняно з assertThrows у JUnit.
