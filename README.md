Висновок
У цій лабораторній роботі було реалізовано надійну підсистему збереження даних для інформаційних сервісів кампусу
результати
Файлове введення/виведення: Доведено здатність програми зберігати свій стан після закриття. Реалізовано два підходи: текстовий формат для зручного ручного редагування та бінарна серіалізація для швидкого збереження всього стану системи
Обробка винятків:** Забезпечено стійкість програми до збоїв. Робота з файлами безпечно обгорнута у конструкцію `try-with-resources`, а логічні помилки даних контролюються за допомогою власного винятку `InvalidCampusDataException`
  Архітектура: Успішно застосовано принцип єдиної відповідальності (Single Responsibility). Логіка роботи з файловою системою `persistence` повністю відділена від структури самої моделі  `model` та бізнес-логіки `service`
