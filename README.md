У ході виконання лабораторної роботи 1 було створено спрощену об'єктну модель системи бронювання номерів готелю. Для перевірки рівності об'єктів класу Room суттєвим полем було обрано roomNumber (унікальний номер кімнати), оскільки він однозначно ідентифікує номер незалежно від його поточного стану (доступний/заброньований). У подальших роботах цю модель можна розвинути, додавши клас Reservation (Бронювання) для відстеження дат заїзду/виїзду, а також впровадити строгі UML-зв'язки типу асоціації або композиції між гостем і номером.

Нормальна прив'язка гостя до номеру (Асоціація). У першій лабі номер просто міняв статус на "зайнято" (available = false), але "не знав", хто саме там живе. Чітке спадкування. Явно визначив, що StandardRoom та SuiteRoom — це прямі нащадки базового класу Room. Усі загальні властивості (номер, статус, поточний гість) лежать у базовому класі, щоб не дублювати код, а специфічні (балкон або кількість ліжок) — у класах-нащадках.
