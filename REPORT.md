# Звіт до лабораторної роботи №13

## 1. Варіант 3.

## 2. Предметна модель
Створено класи `ClassRecord` (для зберігання структурованих даних про заняття) та `ScheduleReport` (для статистичного зведення). Логіка текстової обробки інкапсульована в сервісі `ScheduleProcessor`.

## 3. Ланцюг текстової обробки
1. **Зчитування:** Програма зчитує рядки з файлу `schedule.txt`.
2. **Очищення (String):** Метод `normalizeWhitespace` використовує `trim()` та `replaceAll("\\s+", " ")` для усунення зайвих пробілів.
3. **Валідація та вилучення (Pattern, Matcher):** Застосовується регулярний вираз `^([А-Яа-яІіЇїЄє']+)\s*;\s*(\d)\s*;\s*(\d{2}:\d{2})\s*;\s*(\d{1,3}-[А-Яа-яІіЇїЄє0-9]+)\s*;\s*([А-Яа-яІіЇїЄє\s\.]+)$`. Цей шаблон суворо перевіряє формат аудиторії (наприклад, 204-У1) та часу (ГГ:ХХ). Рядки, що не відповідають шаблону (наприклад, з аудиторією "Ауд-204"), відхиляються.
4. **Конвертація:** Кожна група регулярного виразу (`matcher.group(n)`) використовується для створення об'єкта `ClassRecord`.
5. **Формування звіту (StringBuilder):** З валідних записів та журналу помилок поетапно (без використання конкатенації `+`) будується багаторядковий фінальний звіт.

## 4. Висновок
Під час виконання лабораторної роботи було успішно реалізовано повний цикл обробки неструктурованих текстових даних. Продемонстровано ефективне застосування регулярних виразів для валідації специфічних форматів (номер аудиторії), використання методів класу `String` для попередньої нормалізації та `StringBuilder` для оптимізованого формування багаторядкового виводу.
