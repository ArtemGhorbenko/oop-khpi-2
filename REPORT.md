# Звіт до лабораторної роботи №9

##  Варіант: 3

##  Опис предметної області
Модель описує систему бронювання готелю. Було створено базові класи: `Customer` (клієнт), `Room` (кімната) та `Reservation` (запис броні). Оскільки клієнт може бронювати як конкретну фізичну кімнату, так і абстрактну путівку, доцільно застосувати узагальнення (generics).

##  Узагальнений клас
Створено компонент **`BookingRecord<TClient, TResource>`**.
- **Чому він узагальнений:** Цей шаблон дозволяє типобезпечно пов'язувати клієнта з БУДЬ-ЯКИМ ресурсом. У клієнтському коді продемонстровано дві конкретизації:
    1. `BookingRecord<Customer, Room>` — для заселення в конкретну кімнату.
    2. `BookingRecord<Customer, Reservation>` — для утримання статусу абстрактної броні.
       Це усуває необхідність створювати окремі класи типу `RoomBookingRecord` та `ReservationBookingRecord`.

##  Узагальнений метод та обмеження
Створено метод **`findMaximum(List<T> items)`** у класі `BookingUtils`.
- **Роль:** Знаходить максимальний елемент у довільному списку.
- **Обмеження (Bound):** Використано обмеження `<T extends Comparable<T>>`. Воно гарантує, що метод прийматиме лише ті об'єкти, які вміють себе порівнювати. Для цього клас `Room` реалізує інтерфейс `Comparable<Room>` і порівнює кімнати за місткістю.

##  Додаткове завдання 
**Аналіз:** У лабораторній роботі №5 (Ієрархія медичного персоналу) був метод, який повертав список лікарів.
**Пропозиція:** Замість прив'язки до конкретного типу `Doctor`, можна було б створити узагальнений реєстр `MedicalRegistry<T extends MedicalWorker>`, який міг би зберігати лише хірургів `MedicalRegistry<Surgeon>`, або лише педіатрів. Це суттєво покращило б API програми, зробивши її типобезпечною без використання `instanceof`.

##  Висновок
Узагальнення (Generics) значно підвищують надійність коду, оскільки переносять перевірку типів з етапу виконання (Runtime) на етап компіляції (Compile-time). Клієнтський код позбувся небезпечних приведень типів (cast), а структура класів стала придатною для повторного використання.
