# 2. Предметна модель
Створено сутності `Customer` (клієнт), `Product` (товар), `Order` (замовлення) та перелік `OrderStatus`. Клас `OrderManager` слугує сервісом, що містить колекцію замовлень і використовує Stream API для аналітики та вибірок.

# 3. Використання Stream-операцій
Було реалізовано понад 5 різних stream-конвеєрів. Ключові операції:
- **`filter()`**: Відбір замовлень за статусом `NEW` або `PAID`.
- **`map()` та `flatMap()`**: Витягування імен товарів зі списку замовлень. `flatMap` був необхідний, оскільки кожне замовлення містить вкладений `List<Product>`, який треба було "розгорнути" у плоский потік товарів.
- **`sorted()` та `distinct()`**: Отримання унікального відсортованого за алфавітом списку проданих товарів.
- **`max()` та `mapToDouble().sum()`**: Агрегація для знаходження найдорожчого замовлення та загальної виручки.
- **`Collectors.groupingBy()`**: Групування замовлень по клієнтах, а також складне статистичне групування `groupingBy(..., Collectors.counting())` для підрахунку кількості проданих товарів по категоріях.

# 4. Додаткове завдання: Порівняння стилів
Було реалізовано метод пошуку найдорожчого замовлення двома способами:
- **Імперативно:** Вимагає створення додаткової змінної `maxOrder`, перевірки на порожній список та ручного обходу через `for-each`.
- **Декларативно (Stream API):** Використовує метод `max(Comparator)`, який одразу повертає `Optional<Order>`. Цей варіант значно краще передає *намір* програми (знайти максимум), позбавлений побічних ефектів і безпечніший завдяки `Optional`.
